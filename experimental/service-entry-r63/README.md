# service 连接入口修复 r63：本地候选

截至 2026-10-17，本地代码、发布组装与独立审查已完成；公司仍运行 r62，尚未执行 r63 现场维护和员工验收。此目录保留前端覆盖源码，不包含可直接运行的维护单文件、公司发布回执、私有配置或员工数据。

## 修复目标

选中 service 后，在对应会话显示可填写的连接区域，用户只填 **IP 地址和密码**，点击连接后继续自然对话。用户名 root、端口 22 由受控界面/协议给定；密码经专用连接接口提交，不作为普通聊天内容交给模型。界面显示不能只依赖模型声称“已打开表单”，需要由实际工具事件和会话状态驱动。

## 发布范围

本地候选仅替换个人云端管理器及其受控原生资源挂载：应用文件差异为品牌前端、原生资源来源清单，以及管理器中的两处对应来源常量。其他原生技能、公司 PPT 模板、网关、Office、service broker、数据库、镜像和私有凭据保持原版本。

管理器切换会断开云端工作区并重新建立运行时，持久聊天与文件卷保留。维护流程采用精确 r62 基线核验、持久阶段记录和显式向前恢复；未完成时不能重复 apply。这里没有承诺任何失败都会自动回滚。

## 已有本地验证

- 32 项发布测试：基线/来源守卫、仅管理器变更、启动等待、重复执行和中断恢复。Docker 命令边界使用替代实现，文件事务在 Linux 上实际执行。
- 7 项独立恢复边界测试：第二份终态记录或标记删除的响应丢失、重复 apply、私配/保留服务漂移、终态篡改和预检查失败。
- 在隔离临时目录复现生成器，27 份输出与候选一致。
- 实际 Compose 解析器合并合成 r62 基线和候选覆盖，验证 8 个其他服务不变、旧资源挂载保留、只替换管理器对应挂载与来源配置。没有启动容器或拉取镜像。
- 前端注册和工具事件检查、受控资源挂载启动检查，以及封装文件拆包/来源清单核对。

这些结果用于本地候选审查，不能代替公司当前 Compose 核对、用户浏览器、真实服务器连接和实际查询验收。service 入口故障与新账号工作区重连问题分别处理；本候选不声称解决后者。

## 现场待验证

受控维护前核对当前精确版本；维护后使用已授权测试账号验证输入区域出现、两个字段可填、连接成功、只读服务器查询返回实际结果。不得将密码贴入聊天或提交仓库。通过前保持 experimental 状态。
