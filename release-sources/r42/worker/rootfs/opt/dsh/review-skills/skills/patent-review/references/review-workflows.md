# 审核与对比操作

## A. 申请文本审核

适用输入：说明书、权利要求书、摘要及附图，可合并在一份文档。先列材料清单；用户只上传部分时，其余列“未提供”，不要判定其正式申请没有这些文件。

依次形成以下工作表，避免只读开头或只给语言润色：

1. **结构表**：名称、技术领域、背景技术、技术方案、附图说明、实施方式、权利要求、摘要各自位置。识别实际内容而非仅用标题有无判断；检查顺序及表达的例外见规则目录。
2. **权项表**：权项号、独立/从属、引用对象、主题名称、增加的限定。检查跳号/重号、引用不存在项、后置引用、引用关系矛盾及多项从属引用；识别“权利要求1或2”与“权利要求1和2”的差异。发现解析歧义先引用原句请求确认，不能擅自改成另一个引用关系。
3. **特征支持表**：按技术意义拆分独立权项，给 F1、F2 等编号；每个从属权项列继承特征和新增特征。避免把“连接”与所连接部件拆散，把“同时满足”改成“任一满足”，或漏掉参数范围、步骤顺序、位置/相互作用。对应到说明书原句或图示；功能/效果表述同时核查实现结构/步骤，不能仅因出现同一名词就说支持充分。
4. **实施闭环表**：技术问题、必要结构或步骤、作用关系、参数边界、产生效果的依据。算法方案核对输入、输出、训练/推理阶段、数据与技术场景；生物/化学等特殊领域超出可确认范围时列专业复核项。
5. **图文表**：标号、规范名称、原文位置、附图出现位置、疑似别名或冲突。使用整数、字母后缀和撇号的完整标号；323、323a、431′、431″分别保留，大小写不得擅自合并。正文候选与附图候选取并集。正文提到但未在图中定位的项记“未定位”，不能因未识别就删掉。
6. **摘要表**：技术方案与正文是否一致、摘要是否有未在正文出现的承诺、长度计数的实际方法。中文摘要按规则核对含标点300字限制；读取片段时不得给全文计数。图片文字、公式和跨语言计数有歧义时保留实测统计与人工复核项。

整改建议分为：可直接修正的形式问题、需发明人确认的技术信息、需代理师/法务复核的权利范围问题。不要从语言“更好听”出发扩大或缩窄权利要求。

## B. 技术交底书审核

交底书阶段先帮助补足事实，不要求它已经具备正式申请全部形式。

- 记录最接近的既有方案/现场问题、现有缺点、实际改进点与区别特征；无法确认来源的行业结论标为待证实。
- 沿“结构或步骤→配合关系→实现条件→技术效果”追问缺口。将零散原文组成带引用的技术方案清单；不代发明人填数据、尺寸、试验结果或不存在的实施例。
- 列必要特征、可能替代实现及可选特征，但替代实现仅在已披露或用户确认后作为技术内容；模型提出的扩展统一标“待发明人确认的设想”。
- 给发明人一份按影响排序的补充问题清单，每个问题对应原文缺口和为什么影响理解/实施。
- 若用户要求起草权利要求，先基于确认材料给草案与支持矩阵；将草案和原文严格区分，不把草案内容回填成既有披露证据。

## C. 比较

### C1. 修改前后版本

确认哪份为原申请、哪份为当前修改稿，不能仅按上传顺序推断。

输出：版本身份表→新增/删除/替换列表→每个实质改动的原申请依据→可能影响的权项。区分文字改写和技术信息变化；新增词语不自动等于新增事项，词语相同也不保证技术关系未改变。只有申请前草稿而没有原申请文件时，只能比较草稿差异，不能断定修改是否超出原申请范围。

### C2. 现有技术对比

确认待审权项及申请/优先权信息，为每篇文献记录公开日与可核实来源。日期不明或晚于关键日的文献，不直接作为普通现有技术定案；抵触申请等特殊情况需另行核实，不能只按公开日晚早一刀切。

对每项权利要求建立单篇文献对照：每个完整技术特征、原文披露位置、明确披露/待解释/未在材料发现。只看题名摘要不足以确认完整方案；检索只有摘要时必须保留未覆盖项。

新颖性风险按单篇文献评述；创造性另列区别特征、基于区别的技术问题、已找到的结合动机和技术效果，避免用待审方案作路线图倒推。范围受检索数据库、关键词、语言、时间段与无法访问全文限制。

## D. 产品侵权风险初筛

至少识别：目标专利号、国家/地区、授权权利要求文本及版本、状态核验日期；产品型号/版本、证据类型与发生地域。缺少材料时仍可整理已知信息，但不能给排除风险的结论。

1. 使用授权权利要求及已核实的后续变更，阅读说明书/附图辅助理解；不得用摘要、失效版本或标题代替权利范围。法律状态没有有效来源时标“未核实”。
2. 每项被选权利要求分别拆成完整技术特征，继承全部从属限定；有多个独立权项时不能只审核第1项。用户指定范围外的权项明确未覆盖。
3. 建立表格：`权项/特征ID | 权利要求原句 | 产品对应证据及定位 | 初步对应情况 | 缺口/解释`。对应情况仅用“有对应证据、存在已知差异、材料不足、需专业解释”。不得把产品资料未提到的特征判成不存在。
4. 字面对应情况按全部特征逐项评估。等同、功能性特征解释、审查档案/禁止反悔、许可、现有技术抗辩、法定例外等另列待专业判断，不能通过词语相似或机械比例决定。
5. 输出“需优先复核哪些权项、补哪些产品证据、已发现哪些明确差异”。任何设计规避建议都标注假设，不能承诺改一个零件就一定不侵权；新增事实需要用户或测试记录确认。

若没有有效授权文本或产品技术证据，交付可准备的清单和资料缺口，不制造空表中的对应关系。
