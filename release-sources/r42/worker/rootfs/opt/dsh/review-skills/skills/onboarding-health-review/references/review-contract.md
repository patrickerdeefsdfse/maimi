# 体检材料审阅约定

本技能处理“材料与报告原文”，不创建新的临床标准或招聘门槛。来源核对日期为2026-10-08，后续核对法规仅查询公开标准信息，不发送个人报告。

## 已有文档工具契约

- `office_capabilities({})`：先取得实际支持格式、操作及各操作的`options`。不从参考项目推断Qwen、Tesseract或PyMuPDF存在。
- `office_attachments({})`：只列当前对话附件。选择用户本次指定文件的完整`attachment_id`，格式为`sha256:`后接64位十六进制。
- `office_document({operation:'inspect'|'read'|'ocr', attachment_id:完整ID, options:能力结果支持的选项})`：对附件检查或提取。若输入来自工作区，则将`attachment_id`替换为`input:既有工作区相对路径`，不同时提供两项；这些只读操作不传`output`。
- 当工具返回文本可能超过120000字符、存在截断或分页不完整时，维护已读/未读范围。仅在能力中有真实分页或范围参数时续读，不发明`page_start`等字段。无法续读时明确剩余未读，请用户提供拆分材料或可用文本。
- 用户请求导出时，按能力使用`office_document`支持的`create`、`edit`、`convert`或`pdf`操作，输出为新的工作区相对路径`output`，不能覆盖输入或既有文件。只有成功返回的产物才可作为下载文件交付。

## 读取与证据

每个文件独立建立以下内部记录，按实际返回填写，未知值保留未知：

- `file_id`：本批内唯一编号，如F01；真实文件引用用于工作区定位。
- `subject_group`：默认等于file_id；用户明确同人且报告未冲突才关联。姓名不能成为跨批次唯一键。
- `coverage`：文件类型、总页数是否已知、已读页/段/行、无法读取范围、是否截断、是否用了实际可用的图像识别。
- `report_metadata`：医院原文名称、报告日期及日期类型；不要把打印日期自动视作检查日期。
- `findings`：每项保留原文、真实定位、字段识别状态、医院标记和忠实摘要；不得输出完整身份证号码等无关身份信息。
- `hospital_conclusion`、`hospital_follow_up`：分别保存其原文证据。无内容不补填“正常”。
- `material_checks`：依据用户本次清单或文档完整性；记录来源是“用户清单”还是“文件结构”。

只读到提取后的文本时，以工具返回的段落、行号或可定位标题作为证据位置，并注明“提取文本位置”。不把自行划分的段落计数说成原PDF页码。DOCX没有稳定分页时用章节/表格/段落；PNG/JPG用文件和区域描述。分批提取保留连续覆盖记录，重复段落不算新增读取量。

## 数值与医院措辞

1. 保留原数值文本中的比较符号、小数点、单位、参考区间、↑/↓或H/L。OCR的`0/O`、`1/l`、小数点、阴性/阳性、`<`/`>`存疑时标“识别存疑”，不猜。
2. 不跨单位直接比较，不默认空腹或非空腹，不从姓名推断性别/年龄来选区间；如果报告有两个不同区间而适用对象不明确，保留原文并标需核对。
3. 即使能算出数值超出原报告区间，也只能描述“与报告参考区间的数值关系”；不能推算疾病严重度、适岗、健康分或风险等级。医院没有箭头而计算不一致时标注需核对，不重新作临床定性。
4. “轻度升高，建议复查”不能改写为“肝病、不能入职”。“未见明显异常”不能改写成“无任何疾病、无需再关注”。“建议专科进一步检查”不能弱化为“可忽略”。
5. 医院原文出现危急/急诊/立即就医等词时，将原句与位置置于该文件摘要开头，提醒及时联系医疗机构。不能以未命中词表断言无紧急情况。

## 分开两类结果

**材料核对表**回答：哪些文件/页面已读取，身份标记有无冲突，医院/日期/结论页是否可辨，用户清单中的材料是否提供。默认不设置医院等级、报告时限或必做项目清单。用户提供清单时，不把其中对普通就业的乙肝检测要求当作自动补件要求，而是指出该要求应另行核对适用政策。

**医院记载表**回答：报告实际写明哪些结论和建议、出处在哪、哪些字/值读不清。医院结论可逐字短引，但每次标明来源是医院，不由系统背书。

输出不设置`pass`、`reject`、`hire`、`risk_score`、`job_fitness`等个人判定字段；批次汇总只统计文件和材料处理情况，不排名员工。

## 多人、多文件和增量

默认多文件不合并。用户要求同人合并时，先对同份报告的可辨身份/报告编号核对；出现冲突仅请求确认文件归属，不要求额外提供完整身份证信息。合并只改变展示分组，不能覆盖来源、数值、日期。复查报告与原报告按日期并列，不能用较新结果抹除较旧原文或认定病情改善。新增文件仅追加，避免反复读取所有已核验内容。

处理较多报告时报告真实阶段与完成数，工具失败给错误类别和未读范围；不输出账号令牌、全文日志或其他员工材料。不得宣称所有附件都已读完而只查看首页/末页。

## 职业健康与普通入职

职业健康检查有单独适用范围和机构/医师结论，不能把普通入职报告当成职业健康检查。发现明确职业健康报告时可整理其原文，并列明已提供与未提供的职业健康材料；不根据公司行业、部门名称、生产制造或夜班等泛化背景推断个人职业禁忌或自动判定岗位适任。

若用户提出“更宽松”或“别太严格”，理解为减少无依据的医学与招聘推断、忠实保留医院原文、不给轻微箭头自动升级，不理解为篡改数值或忽略医师建议。

## 官方依据使用

读取`official-sources.json`中的来源说明，需要规则说明时引用对应URL和版本。来源用于说明工作范围与限制，不能替代个人报告事实。医学参考标准的发布/生效日期可能不同，不能把将来生效条文用于当前结论；旧报告的临床判断不由本技能用新标准重新裁判。

只有用户要求导出时才使用当前实际可用的文档生成能力。对话结果和导出都依工作区访问和留存机制处理，不另建数据库、云端OCR接入或员工长期画像。
