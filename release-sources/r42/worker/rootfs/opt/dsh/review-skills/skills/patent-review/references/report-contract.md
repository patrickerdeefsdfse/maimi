# 证据与交付规范

## 文件与锚点

为每份文件建立最小记录：

| 字段 | 要求 |
| --- | --- |
| document_id | D1、D2；同一报告内唯一 |
| filename / attachment_id | 使用系统返回的原名及附件引用，不输出服务器存储路径 |
| role / version | 申请稿、原申请、修改稿、授权权利要求、对比文献、产品资料等；未确认就写未确认 |
| locations | 实际页码，或小节与段落编号；PDF显示页与印刷页不同应说明 |
| read_coverage | 已读取范围、总页/段数是否已知、图片/OCR/表格处理状态 |

每条发现采用稳定 ID，例如 PR-001。证据锚点示例：`D1 / 权利要求3 / P0042 / “所述第一连接件与…”`。引句须与实际读取内容一致，宜保留最短必要上下文。OCR 的引句应注明“OCR待原图确认”。外部全文引句遵守当前工具引用限制，优先用概述和明确位置。

不把“P0042”伪称专利原有段号；自编段号注明“本次提取段号”。若原文已有 [0032]，同时记录原段号。无稳定段号时用小节、可搜索原句及上下文定位。

## 每条发现

| 字段 | 内容 |
| --- | --- |
| id / category / priority | 如 PR-001 / 权项引用 / 高；说明高低的实际影响 |
| observation | 原文可确认的事实 |
| evidence | 至少一个文件位置与真实引句；跨文件冲突分别引用两处 |
| inference | 为什么存在问题/风险；与已确认事实分开 |
| basis | 可适用的 rule_id 与法条/官方来源；技术性建议不伪装成强制法规 |
| recommendation | 可执行修正或需补充的技术事实，不捏造实施内容 |
| status | 待修正、待确认、证据不足、已核对未见该项问题；不要默认“已通过” |

“已核对未见该项问题”只用于该项检查且覆盖充分；整体审核不能因无问题行而自动通过。

## 最终报告结构

1. **本次结论与范围**：审核对象/版本、适用模式与法域；最先处理的1–3项风险；结果为辅助审核。
2. **问题清单**：按高/中/低排序，每条包含原文定位、事实、影响和建议。没有问题时给已完成检查和实际范围，不硬凑风险。
3. **对应矩阵**：文本审核给权利要求支持及图号映射；比较给版本差异或逐篇文献特征表；侵权初筛给逐权项、逐特征、逐产品证据表。
4. **检索与规则依据**：实际用过的官方来源/专利文献、日期、真实渠道与局限；没有检索时写“本次未做外部现有技术检索”。
5. **未覆盖与下一步**：缺失文件、未读页、扫描/OCR缺口、未核实法律状态或日期、需要发明人/代理师/法务确认的事项。

不要在报告里输出凭据、会话内部信息、工具隐藏路径或软件实现细节。进度信息应基于实际阶段，例如“已读取18/30页、正在核对权利要求”；总数未知时不用虚构百分比。

## 可选结构化输出

用户或现有工作流需要 JSON 时使用以下形状；字段无证据时用 null/空数组并在 coverage 中解释，不猜填。

```json
{
  "schema": "megmeet-patent-review-v1",
  "mode": "application_review",
  "jurisdiction": "CN",
  "documents": [],
  "coverage": {"text": [], "figures": [], "ocr": [], "unreviewed": [], "external_search": "not_requested"},
  "findings": [],
  "claim_charts": [],
  "drawing_label_map": [],
  "sources": [],
  "next_actions": [],
  "conclusion_scope": "辅助审核；仅基于本次实际读取材料"
}
```

建议 findings 内字段：`id, rule_id, priority, observation, evidence[], inference, recommendation, status`。证据项含 `document_id, locator, quote, origin`；origin 区分 `native_text, ocr, figure, external_source`。模型可供人工复核的建议与文件原文分栏存放。

## Word 批注与修订

参考项目的原生 Word 批注能力不能视为麦米已经安装。先以 Office 实际能力为准：具备原生批注且锚点可核对时才用；否则交付单独审核报告。不能在普通编辑工具中伪造 OOXML 操作结果。

若能力可用，使用输入副本；每条批注锁定同一段的原句，核对 Unicode 字符位置而非浏览器UTF-16长度。重新读取发现文字或版本变化时停止套用旧锚点并重新定位。包含文本框、域、图文混排或跟踪修订的段落无法保证不损坏原文时，保留报告中的定位意见，明确该处未写入批注。

同一范围内的批注与修订冲突、跨段选区、无原句匹配、无法导出或导出验证失败都不能宣称成功。新文件生成后检查可下载、文件类型、关键正文和意见是否保留；工具仅生成普通DOCX时不宣称Word原生修订已验证。原始文件始终保留。
