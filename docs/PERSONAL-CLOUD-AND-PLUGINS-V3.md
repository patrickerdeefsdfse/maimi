# 桌面0.4.0：个人本地、个人云端与企业插件

本说明覆盖V2部门/小组云工作台方案。保留原有数据库记录和备份供后续处置，不再提供部门/小组浏览、共享、资料发布入口或/v1/cloud公共接口。

## 用户行为

- 首次登录仍由用户选择本地工作区。归档所有本地工作区后也不会自动选云端。
- 左侧固定置顶“云端工作区”，没有删除/重命名/归档菜单。只有手动点击才连接服务器；未发送文字、附件和运行任务会阻止切换，避免丢稿。
- 云端工作区属于员工本人，按稳定工号绑定。聊天、原生工具执行和文件位于长沙Linux的个人容器/独立卷；回到本地后看到自己的Windows原生历史。界面明确显示当前云端状态并提供返回本地。
- 企业插件是原生输入中的选择标签，小弹层展示本人授权插件。选择即附带当前对话，不再选择授权工作台。真正发送时只上传明确选择的附件；插件结果位于当前原生会话的结果卡，并保存在服务器。
- 模型目录完整取自当前员工TokenKey授权列表；默认优先deepseek-flash-v4.1。若该员工未获授权，不伪造可用性，会说明并使用本人已有可用模型。0.4.2起取消“刷新模型”按钮：进入、连接恢复、窗口重新聚焦以及可见页面每60秒自动同步到DSH原生模型选择器。通过原生settings/update热更新，本机和云端均不重启Host、不刷新页面、不改草稿或仍获授权的已选模型。明确空目录清空全部可选模型；网络失败保留上次列表并提示，每次模型调用仍由服务器重新检查权限。

## 服务边界

桌面主进程只保存短期应用凭据，原生页面只能访问自己的随机本机端口。云连接经固定Gateway转发，前端不能提供服务器、owner或容器参数，浏览器Cookie不会转发到云DSH。服务器按可信IAM账号校验每次HTTP请求和持续WebSocket会话；真实TokenKey与IAM token留在服务器模型代理。

Gateway负责身份/目录/插件授权/模型代理。私有personal-cloud-manager独占Docker接口，只创建固定镜像、固定内部网络、受限资源的个人worker。worker无Docker接口、无其他员工卷，也没有IAM client_secret或管理凭据。每个员工有独立/state和/workspace持久卷。失效/空闲回收容器保留卷；不允许客户端创建任意Host、挂载或删除工作区。默认同时2个worker，单个768MiB、1CPU、128PIDs；这是当前小内存机器的起始限制，不是千人并发容量承诺。

插件使用发布时登记的固定runner及版本，管理员可按员工授权、撤权；知识问答runner调用本人的模型代理。内置本地合成摘要仅测试环境启用。插件上下文以员工+原生会话完整ID+local/cloud绑定，保留DSH session-UUID前缀，禁止重试改绑。资料与结果始终再做权限检查。现阶段不接受任意用户上传插件执行代码，不自动迁移旧项目。

## 升级与部署

DSH核心固定0.1.6-alpha.1，236包；企业扩展3.0.0，工作区适配1.0.0。上游源码先校验原始SHA，再应用有限插槽/品牌/首开声明/新会话反馈适配，输出SHA和资源摘要进入兼容清单。原生RPC变化必须重跑Windows+Linux真实界面、模型、历史与隔离验收，不能只改版本号。

服务器离线包包含五个Linux/amd64镜像、迁移、专用Compose、配置向导与Nginx片段；Windows公司桌面不需要WSL/Docker。真实IAM测试注册与公司网络联调仍需在长沙完成，固定回调https://platform-ai.megmeet.com/v1/iam/callback。本机模拟验收不能替代生产验收。

当前没有原生文件卷硬字节配额、跨设备离线同步或正式签名自动激活。生产应为个人卷设置存储预算、监控备份和容量验收；不把工作区插件PG附件配额误称为整个原生文件卷配额。
