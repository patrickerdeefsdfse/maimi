# 部署与运维

> **2026-10-17 状态更新：** 本仓库已整合 r54/r56/r59/r61/r62 公开应用增量。较早版本叙述用于解释历史，当前状态以 [当前架构与版本](../CURRENT-ARCHITECTURE.md) 和 [组件源码映射](CURRENT-SOURCE-MAP.md) 为准。r63/r64 仅在 experimental，不是已部署能力。根 Compose 不能直接复原当前线上 r62。


本文区分源码管理、构建制品和公司运行环境。当前公司网关已应用 r56、管理器保留 r54；源码基础仍主要为 r52/r53。直接拉取本仓库不会自动更新服务，也不应把源码归档覆盖到运行目录。

## 当前交付方式

当前发布由管理员经既有堡垒机会话执行已审查的版本维护工具。工具校验版本、文件哈希和服务身份，准备备份，按限定范围切换，再返回阶段与健康回执。代码提交、版本切换和员工业务验收分开记录。

公司 GitLab 已完成源码提交，但未配置并验收 GitLab Runner、自动镜像晋级或自动部署。已有本地测试、构建、维护与更新脚本，不能等同于已完成持续集成和持续部署。

```mermaid
flowchart LR
    Source[独立变更与代码评审] --> Test[相关本地测试]
    Test --> Artifact[构建与制品审计]
    Artifact --> Freeze[冻结清单与恢复方案]
    Freeze --> Check[现场只读基线检查]
    Check --> Window[维护窗口切换]
    Window --> Health[健康与范围核对]
    Health --> Acceptance[员工业务验收]
    Acceptance --> Record[版本记录与后续推广]
```

流程中部分步骤已有脚本支持；Runner、环境晋级和无人值守编排仍是后续建设内容。

## 新环境部署前提

| 前提 | 需要确认的内容 |
| --- | --- |
| 源码与制品 | 对应发布源码、基础镜像、完整 DSH/Office 运行时、覆盖文件及哈希清单 |
| 入口 | 公司 HTTPS 域名、可信证书、准确 Nginx 路由与长连接代理 |
| 身份与模型 | IAM 注册和回调契约、客户端续期、个人 TokenKey 服务与允许模型 |
| 平台服务 | PostgreSQL、Redis、迁移任务、网关、管理器、Office、下载与保留维护 |
| 存储 | 数据卷目录、容量、UID/GID、文件与数据库联合备份、密钥保存与恢复 |
| 企业能力 | MES 与各供应商授权、服务端私有配置、实际业务额度及可达性 |
| 运维 | 监控、告警接收、维护窗口、恢复责任人和隔离测试环境 |

根 Compose、`ops` 和历史维护工具是部署资料，未组成已验证的全新机器通用安装器。部分脚本固定原环境目录或基础发布，不能在新机器直接执行；应先整理对应版本的部署清单并在隔离环境重建。

## 配置与秘密

参考 [CONFIGURATION.md](../CONFIGURATION.md)。区分可版本管理的配置模板、运行环境参数和秘密值。IAM、模型、数据库、供应商 Key、签名私钥及私有电话规则由服务端受限文件或公司秘密系统保管，不进入 Git、命令参数、模型提示词或原始请求日志。

配置检查只证明权限、文件身份和契约符合预期，不能证明账号余额、供应商额度或真实业务可用。更换账号时，先分阶段保存和校验，再在限定维护操作中启用，保留上一份配置的恢复材料。

DSH 工作区只使用受限租约和固定访问边界。管理器持有 Docker 管理能力，需要独立保护；不能为方便调试把 Docker socket、数据库或工作区原生端口公开给客户端。

## 发布操作原则

1. **核对现场。** 以最新发布回执和源码 pin 为准，确认当前网关、管理器、运行时与部署范围；不要用过时本地默认值推断现场。
2. **准备独立候选。** 保留正式制品与数据，检查依赖、许可、目标文件、版本组和安装器/镜像内容。
3. **只读预检。** 使用对应版本工具的 `--check` 等只读阶段；出现 `STOP` 时保留回执，不删除检查项或反复盲跑。
4. **限定维护范围。** 按已声明影响执行切换；网关重启可能中断请求，管理器更新可能影响云端连接。不要顺带重启无关服务。
5. **核对回执。** 检查实际版本、健康、服务变更集合和备份位置；脚本执行结束不等于业务验收。
6. **实际业务验收。** 用获授权的最小场景检查登录、文件、模型和本次变化，记录用户确认与限制。

历史工具可能包含 `--apply-maintenance-window` 等操作阶段，但脚本通常绑定特定基线。本指南不提供绕过这些约束的通用生产命令。

## 桌面分发

公司正式桌面为 0.13.0；0.17.0 候选做过本地成品验证，尚未发布到公司自动更新。桌面构建、安装器生成、更新清单签名、下载站启用和员工试装是不同步骤。

发布前核对真实 ASAR 白名单、源码字节、完整运行时资源、部署配置及安装器内载荷；再在独立用户数据目录做启动验证，并安排单机试装。更新清单签名与 Windows 安装器 Authenticode 签名不是同一种保障，不能互相替代。

自动更新能力存在，不代表每个候选都已签名或发布。只有完成制品与信任链核验、下载站启用和用户验收后，才应扩大分发范围。

## 健康与可观测性

| 检查层次 | 说明 |
| --- | --- |
| 进程与容器 | 是否运行、重启、OOM、磁盘和可用内存 |
| 基础就绪 | 网关、数据库、Redis、管理器策略等是否满足启动条件 |
| 工作区连接 | 原生 HTTP/WebSocket、租约、工作区归属和会话恢复 |
| 企业接口 | 凭据契约、供应商工具、额度、路由和实际响应 |
| 用户结果 | 文件能否读取、任务结果是否完整、成品是否正确 |

`READY` 不能替代最后两层。HTTP 101 只证明握手升级，不证明后续原生消息、历史或技能工作正常。

采集采用有界、闭集元数据：阶段、耗时、计数、状态码和固定错误分类。不要常规记录完整 Cookie、Authorization、文件名查询参数、聊天、附件正文或完整容器环境。当前相关入口有意关闭原始访问日志，不能假定历史请求 URL 总能从服务器回溯。

## 备份、恢复与清理

备份至少包含：PostgreSQL、员工原生状态卷、工作文件卷、平台文件卷，以及单独受控保存的必要加密配置和密钥。镜像与 Git 源码不是业务数据备份。

当前维护资料包含停机一致性备份与哈希验证思路。执行前确认相关写入已经停止，保留所有权和数值 UID/GID；先在隔离环境恢复，验证登录、历史、文件和任务引用一致，再制定正式恢复步骤。仅压缩包可解压、SHA 正确，不等于完整业务恢复成功。

关闭工作区后的两小时保留是计算策略。数据保留另有服务端策略与删除栅栏，当前代码包含可选的 30 天整工作区不活跃清理；实际启用状态和告知规则需按现场核对。旧“90+30 天回收”资料不应作为现行承诺。

清理只能针对明确属于当前应用的对象，不能使用全局 Docker 清理或递归删除数据根目录来释放空间。逐员工硬磁盘配额、异地灾备和恢复目标需要独立建设及演练，不由普通命名卷自动提供。

## 常见问题定位

| 现象 | 优先区分 |
| --- | --- |
| 长时间加载/重新连接 | IAM 会话、原生连接、Host 冷启动、资源准入、前端模块和恢复栅栏 |
| 技能列表有项目但不可执行 | 当前会话选择、服务端授权、执行许可、连接器配置和供应商响应 |
| 任务结束但没有成品 | 结果是否要求补充输入、文件是否读取成功、模板/照片/必填项是否齐全 |
| Excel 或文档读取失败 | 上传实际格式、企业透明加密、损坏文件、格式支持及具体读取器 |
| 物流无轨迹/预计时间 | MES 运单、承运商、电话校验、路线信息、额度和供应商实际结果 |
| 维护出现 STOP | 版本或文件漂移、配置身份、并发外部变更及工具绑定的旧基线 |

r56 企业上传已获本次用户确认：技能与普通聊天均能正常读取。对旧加密附件，应在修复后重新上传；服务器不会把已保存的企业密文自动解密。若仍收到明确加密提示，应核对公司安全网关策略，而不是另存、改编码或绕过检查。

## 推广前的建设清单

以下是建议与待建设项，不是已完成状态：

- **可复现交付：** 将当前多轮覆盖整理为标准镜像构建；补齐同版制品、许可、依赖锁和源码与现场的版本映射。
- **GitLab 工作流：** 配置合适的分支权限、合并请求评审、Runner、制品仓库和保留策略，先验证只读与合成测试流水线。
- **环境晋级：** 建立隔离测试、预生产和生产门禁；自动部署必须能控制影响范围、恢复与审批，不从提交直接改生产。
- **业务回归：** 保存合成端到端场景，覆盖双账号隔离、撤权、取消、多种文件、企业加密上传、结果完整性及成品下载。
- **容量与成本：** 压测并发进入、活跃工作区、文档转换、内存/磁盘和模型额度；制定准入与费用告警。
- **运行保障：** 建立监控、告警、值班责任、变更记录、恢复演练、备份可用性及服务目标。
- **数据治理：** 确认保留期限、删除规则、权限复核、硬配额和秘密轮换流程；按公司要求记录访问审计。
- **桌面推广：** 完成制品信任链、单机试装、小范围验证和更新恢复，再扩大分发。

这些事项应分别有负责人、验收证据和维护规则，不能仅以“已经接入 GitLab”视为完成。
