# 个人云端存储与恢复（2026-09-18 候选）

## 数据分工

| 数据 | 位置 | 生命周期 |
|---|---|---|
| 本机聊天、工作文件 | 员工电脑的 DSH 原生目录 | 不自动上传，不受服务器清理影响 |
| 云端聊天原始日志、DSH 状态 | 每员工独立 `-state` 持久卷 | 已验证格式按 90+30 天规则；不兼容格式保留并报告 |
| 云端会话结构化头、事件、员工归属、清理回执 | PostgreSQL `personal_cloud_history*` | 闲置同步；与原始记录清理/恢复对账 |
| 用户在云端工作区创建的文件 | 每员工独立 `-files` 持久卷 | 不随聊天到期删除 |
| 企业插件显式上传的项目文件 | 独立 `platform-files` 持久卷 | PostgreSQL 保存权限、散列、大小与对象键；不随聊天到期删除 |
| 现有数据库内附件 | 原 PostgreSQL 字段 | 保持可读；本次不自动搬迁或删除旧附件 |
| 项目向量索引 | Milvus，按项目启用 | 派生索引；原始文件和权限以平台记录为准 |
| 项目全文索引 | Elasticsearch，按项目启用 | 派生索引；普通聊天不自动触发搜索 |

文件路径用员工及作用域的摘要分区、内容摘要命名，不采用上传文件名拼接路径。读取需先经过平台权限检查，再校验文件大小和摘要。文件卷与数据库必须成套备份，数据库备份不包含这些文件。

## 90 天未活动 + 30 天恢复

每 5 分钟轮询一批员工。只有本人云 Host 已退出且状态卷无其他运行容器使用时才检查，正在使用的云工作区会延后。结构化历史进入 PostgreSQL 并提交后，才允许将完整原生会话目录移入同卷回收区。最后活动时间综合原生事件、文件修改时间及恢复回执，连续 90 天未活动才入回收区，进入后保留 30 天。

桌面“云端历史回收站”只显示本人记录，可提交恢复。请求排队后，返回本机并让云端闲置，下一轮维护原位恢复同一会话；不强制结束正在执行的任务。恢复后重新计算 90 天。超过恢复期限后删除该聊天原始目录与 PostgreSQL 事件内容，留下不含聊天正文的处理回执。项目文件、工作区注册、设置、附件目录不在本次删除范围。

为避免损坏 DSH，当前自动清理仅支持固定 0.1.6-alpha.1 的格式3。存在父子/分叉/子代理关系、未完成轮次、未知文件、损坏日志、符号链接或超出扫描限额时保留不删。单会话压缩日志上限4MiB、解压上限16MiB、单批最多2000会话；超限需要专项归档，不静默跳过后继续删依赖项。PostgreSQL 的 `personal_cloud_storage_jobs` 保存同步状态与跳过数。原生状态卷是运行事实来源，PostgreSQL 是结构化投影，活跃聊天不是逐条实时写入 PG。

## 检索服务边界

Milvus 2.6.24、Elasticsearch 8.19.21 已有本机隔离安装和合成读写证据。当前通用聊天和文件摘要插件不要求它们，主部署包默认不启动。具体企业项目接入时，由服务端插件声明需要的检索能力，并限定项目/员工授权范围；不要把整个员工聊天库自动向量化，也不要让客户端直连数据库。现有插件文本处理不等于已经完成所有项目的向量检索实现。

## 备份与上线边界

所有持久卷位于公司 Docker 数据目录。新实例不删除旧项目或旧卷。删除任何旧运行版本前，应把 PostgreSQL、原生 `-state`、工作文件 `-files`、`platform-files`、必要的加密密钥及配置共同备份到另一台机器，并验证恢复。镜像包不能代替数据备份。

本机验证不代表长沙现场验收。真实 IAM、目录授权、个人 TokenKey、HTTPS 路由、备份目标和容量需部署后验证。默认同时2个云 Host，不能据此宣称支持上千并发。
