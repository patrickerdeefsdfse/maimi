# DSH 升级与公司扩展边界

更新日期：2026-09-21。本地候选已实施；没有连接或修改长沙服务器，没有重做发行 ZIP/EXE。正式 IAM 目标按用户要求改为 https://iam.megmeet.com，实际注册/网络仍待公司联调。

## 1. 独立发布的边界

| 部分 | 负责什么 | 升级方式 |
|---|---|---|
| 原生 DSH 版本组 | 前端、npm runtime、原生 RPC 与250个同版包 | 一组固定版本整体构建验收 |
| DSH adapter | 启动参数、模型 profile、启动认证、原生数据格式、兼容检查 | 跟桌面代码签名发布 |
| MEGMEET UI 扩展 | 品牌、固定个人云端入口、企业插件选择 | 独立源码模块，受版本及上游摘要守卫 |
| 桌面外壳 | 浏览器登录、窗口、本地进程/数据目录、云接口桥 | 桌面安装包 |
| 公司服务 | IAM、个人 TokenKey、个人原生云Host、员工插件授权与任务 | 独立长沙镜像包及 API版本 |
| 独立连接器与本机工具 | 钉钉/搜索后端；专用浏览器/Windows窗口驱动 | 固定工具协议，DSH专用适配集中在 toolkit/adapter |

DSH更新不应要求改IAM、员工权限或者业务插件后端。公司功能也不能直接读取
DSH内部数据库来实现共享；云数据使用自己的稳定接口和存储格式。

企业交互模块通过原生slot和受摘要保护的品牌入口注入。仍有四个显式上游
bundle适配点：品牌slot、首屏文字/Preview、内测声明、固定工作区入口/新会话反馈。它们集中在构建overlay，
没有分散手工改node_modules。上游摘要不一致时必须重新适配，不能跳过守卫。
这是减少未来升级工作，不是承诺任何上游改动都能无修改替换。

## 2. 当前受支持的版本组

- 当前候选 DSH runtime/native frontend/npm RPC SDK：0.1.6-alpha.2，250个DSH包同版。旧已交付0.7.1仍携带alpha.1/236包，原字节保留。
- Windows Node：24.13.0，固定本机已核验binarySHA。
- MEGMEET branding：megmeet-assets-r5；企业扩展：3.3.0；固定工作区适配：1.0.0。
- 企业服务协议：megmeet-personal-cloud-v1 / megmeet-plugins-v1 / megmeet-connectors-v1；原生前端与远端RPC同版运行。
- 原生历史格式标记仍为dsh-0.1.6-alpha.1-native：alpha.2仍使用已验证的format 3，包升级不等于持久格式升级。历史维护严格接受alpha.1或alpha.2同版组合，拒绝混版及未知版本。

Windows独立候选位于 `output/upgrade-20260920/candidate-alpha2`；静态版本、品牌/模型导航、真实聊天工具确认、历史副本续聊均已验证。Linux候选为 `*:alpha2-candidate-20260920`，仅本机镜像，尚未作为公司发行。

兼容窗口已实际验证：原0.7.1归档中的auth/runtime-host/cloud bridge与其原alpha.1 runtime，连接新Gateway/alpha.2云Host，可登录、加载云端原生页面、聊天、重载恢复、读取新云连接器目录。只在内存把测试地址改到隔离loopback，旧归档SHA未变；证据 `output/upgrade-20260920/legacy-cloud/result.json`。因此可保留0.7.1的已测核心云聊天路径作为更新窗口；不能推断更早桌面、所有新功能、公司TLS/真实IAM均已兼容。云桥不做任意RPC版本协商，新DSH版本仍须重新测试。

社区扩展另列 `community-manifest.json`：当前包含文件修改对比、主题、界面组件支持、用量统计四项，固定Git提交、MIT许可、逐源码和编译文件摘要。Windows和Linux采用同一清单；启动时校验，不从浮动latest在线安装。它们不等同于公司业务任务插件，不能获得IAM、个人TokenKey或绕过业务授权；新增工具、MCP、联网搜索需单独审核实际权限及依赖。

`runtime/compatibility-manifest.json`记录实际版本组，连同npm锁、served resources、
adapter和扩展摘要形成完整候选记录。启动也检查版本组与已安装模块；离线候选
检查额外核对所有声明的原生前端资源。静态校验状态不等于浏览器、模型、公司
认证或者旧历史恢复验收。

旧部署使用过Python SDK/wheel；当前Windows桌面走npm runtime/native RPC，
因此清单明确写SDK种类。不能把以前的Python wheel当成当前已验证组件。

## 3. 升级步骤

1. 独立candidate目录安装指定上游版本，保留现用程序与本地个人数据。
2. 审核上游变更，更新adapter、overlay固定版本/原始摘要，明确数据格式是否变更。
3. 用固定依赖生成native runtime和公司扩展。默认不浮动获取latest。
4. 运行`verify-dsh-candidate.cjs`，以及adapter、UI、桌面、后端相应测试。
5. 合成A/B账户验证多轮聊天、个人Key归属、插件/附件确认、云ACL、退出；
   用独立历史副本验证重启后的历史读取和续聊，不在唯一真实数据上试迁移。
6. 验证完成后再准备桌面与服务器发行包、SHA、版本组和证据，随后做正式IAM公司联调。当前用户要求优化完成前不重新打包，旧r9/r10包保持原字节。
7. 有公司签名身份后签manifest及Windows installer，灰度小批员工，再扩大范围。

全新上游版本默认被现adapter拒绝。审核后产生新adapter与整套发布；不是修改
一个版本字符串就视为兼容。完全兼容时主要验证版本组；有破坏性变化时主要
修改adapter和少量overlay，公司服务接口保持不变。

打包与受控刷新完成后，执行只读成品审计：

```powershell
node new-system/desktop-local/scripts/audit-packaged-candidate.cjs --company
node new-system/desktop-local/scripts/audit-packaged-candidate.cjs --local
```

审计实际asar的文件白名单和源码字节、公司HTTPS配置、fixture隔离、EXE内嵌
Electron asar摘要、完整runtime版本组及artifact记录。只写evidence，不修补包。
应在构建/刷新结束后执行；发现制品在检查期间被改动会失败。成品完整性通过仍
不代替实际启动、浏览器操作、公司IAM与模型测试。

## 4. 数据不跟安装目录走

个人数据在员工本机账号分区，与runtime/应用版本目录分开。新版程序不删除
或直接覆盖历史；个人云端文件、上下文、权限在服务器存储边界内管理。
`megmeet-native-data.json`只标记当前支持格式，绝不重写原生session文件。
原有未带标记数据仅作为本机已部署同版0.1.6-alpha.1的历史延续；不把未知更早或
更高版本目录导入当成已兼容。带未知格式标记时启动失败，需要专门迁移。

本轮没有开发任意DSH数据格式转换器。未来格式变更必须提供独立迁移和副本
恢复测试；签名有效也不能跳过要求。

## 5. 自动更新的已实现与未实现

桌面0.5.0已实现公司HTTPS源、Ed25519固定公钥验签、版本/序号防降级、清单有效期、
安装器大小/SHA256校验。启动和每6小时检查，后台下载，正常退出并完成Host清理后
交给NSIS安装；不强杀正在聊天的程序，系统关机时不启动安装。旧离线候选暂存工具
仍保留用于构建验收，不能与现在的安装式自动更新混为一谈。

签名私钥由维护电脑在仓库之外保存；服务器只提供公开清单和安装器。真实隔离NSIS
安装/升级/卸载保留数据、本地成品和签名传输已验证，尚未发布到公司域名。
Windows Authenticode企业证书尚未接入，不能把更新清单签名等同Windows发布者信任。
现阶段还缺历史更新缓存清理、安装失败回执及正式公钥轮换流程，应在后续桌面版本补齐。

## 6. 当前工作区约束

最新产品只提供个人本机和个人云端两类原生工作区。部门/小组云工作台已经移除，
不能根据旧文档重新开放。云入口固定置顶、不可删除且只能手动进入；每员工独立
Linux原生Host和持久卷。网页只提供本人的云端，桌面保留本机/云端。每次登录有独立租约，第二端复用同员工Host与卷；退出一端仅撤销该端。每员工Host一次只运行一段对话任务，另一端等待当前任务结束后继续，不是多人协同编辑或离线合并。

企业插件直接附带对话，服务器按员工和插件版本复核授权；它不要求选择部门工作台。
本机文件只在用户明确选择上传时离开电脑。业务插件需实现并注册相应执行器，
现有框架不等同各部门项目已经完成。原生历史仍固定支持的DSH格式，升级格式时
须新增迁移与恢复验证；插件接口独立并不意味着底层原生日志格式天然兼容。

新版原生插件页、Office预览与文件对比继续使用上游实现；会话输入区保留紧凑的企业工具选择，承担按用户、客户端、会话显式选择及停止职责。它和上游通用插件安装管理不混用权限。

Linux只读/noexec运行策略保持。alpha.2本机模块缓存会尝试从/tmp加载动态库，worker设置NARB_DISABLE_NATIVE_CACHE=1直接使用镜像内已安装模块，避免改变/tmp挂载策略。manager命名空间限制为3至30字符，以容纳员工摘要后仍满足DNS单标签63字节上限。完整网页/桌面真实本地链路32项及原生worker多端4项通过；公司8GB环境容量仍需实测，默认2个活跃Host未提高。
