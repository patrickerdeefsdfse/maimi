# 运维与验收

## 看板

从麦米首页进入「运行监控」。看板向已登录员工展示概况，受限操作和明细另行校验权限，默认显示概况，并支持日、周、月视图和用户搜索。桌面端上报版本和心跳。心跳与用户实际操作分开计数。看板只保存运行统计，聊天正文、文件内容和登录凭据不进入监控历史。

| 重点 | 读图方法 |
| --- | --- |
| 应用入口 | 分别查看内部健康、应用就绪、服务器到外部站点的 DNS、TCP、TLS 和 HTTP 检查。员工实际访问还应从员工网络验证。 |
| 主机与节点 | 主机实际可用内存和 K3s 节点工作集采用不同口径。结合节点压力、持续趋势和排队情况判断是否扩容。 |
| 聊天与沙箱 | 查看正在分配的实例、等待请求数和最长等待时间。缺样显示未采集，共享资源不能平均摊算为某个员工的用量。 |
| 文件 | 个人提醒额度不预留磁盘。超额借用共享池余量，平台保留总容量和最低余量保护。桌面本地文件不计入 NAS 已用。 |
| 用户与桌面 | 日活、周活、用户排行、分页和版本分布以真实事件为准。历史从接入时开始积累。 |
| 备份 | 分开核对最近成功备份、恢复验证和独立备份位置。NAS 备份策略、整机故障切换和站外告警按实际完成情况验收。 |

## 统计保留

| 数据 | 时长 |
| --- | --- |
| 分钟明细 | 3 天 |
| 小时汇总 | 30 天 |
| 日汇总 | 180 天 |
| 逐用户日记录和设备记录 | 30 天 |
| 幂等回执 | 1 天 |

由定期任务汇总和清理，跨 AP 加锁。数据库表占用会随运行情况变化。不要根据刚上线时的样本推算长期固定空间。

## 发布后检查

rc.2 的 Linux 维护镜像使用已验证的企业运行时作为基础层。离线重装 Node 依赖时，先校验共享制品 `maimi-r116-linux-vendor.tar` 的 SHA256 `73efc89c821a1f1235e60cb344614550c945be20dc7a21b1efc62ff76a5f741f`，再解到 `server/worker/dsh`。归档中自带 `vendor/` 目录，仓库的 `package-lock.json` 对每个本地包固定了完整性摘要。普通维护构建直接复用镜像里安装好的依赖。镜像、导入与切换回执位于本地资料库的 `output/maimi-rc2-20261112/`。

1. 核实两个 AP 的健康响应和实际版本。
2. 检查新会话启动、历史恢复、普通消息、文件读写和权限。
3. 在办公网络验证 IAM、下载、断点续传和安装包摘要。
4. 核对数据库复制、备份恢复、告警渠道和 NAS 现场备份状态。记录已验证、未采集与等待现场确认的项目。

2026-11-05 正式站实测：员工重新上传同一份受保护的 Excel 后，已能在会话中读取。旧会话曾出现首次文档读取超时，后续工具返回 `ATTACHMENT_CACHE_OUTCOME_UNKNOWN`。两种情况要分别记录；复测时同时核对上传回执、缓存就绪状态、执行工具响应和最终读表结果。
