# 旧系统最终清理手册

这是新系统通过验收后的人工操作手册，不是当前执行命令。清理旧系统前必须由负责人确认，并保留恢复窗口。

## 必须满足的条件

- 新系统已在独立 Compose project、网络、目录和数据卷稳定运行。
- GitLab 已保存最终代码、Compose 文件、迁移版本和镜像清单。
- PostgreSQL、Milvus/MinIO、Elasticsearch、Redis、文件目录均完成备份恢复演练。
- SSO、权限、普通 DSH 对话、流式恢复、企业插件、文件和知识库验收通过。
- 已记录旧容器、旧卷、旧目录、旧 Nginx 配置和旧镜像标签。
- 已安排回滚负责人和明确回滚截止时间。

## 清理顺序

1. 停止新入口流量变更，确认没有进行中的任务。
2. 再次导出旧系统配置清单和数据库/文件备份校验值。
3. 将入口切换到新系统，观察健康、错误率、登录和对话恢复。
4. 在回滚窗口内保留旧容器、旧目录和旧数据卷，只停止旧入口服务。
5. 回滚窗口结束且负责人再次确认后，才逐项归档旧项目和旧镜像。
6. 最后才考虑删除旧 Docker 卷和旧目录；删除前必须人工核对绝对路径，禁止使用未经核对的通配符。

旧系统的删除属于不可逆操作。本手册不包含自动删除脚本，也不应在测试通过前执行。
