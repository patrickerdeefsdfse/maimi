# 麦米统一机器人接入交接

这份交接用于配置一个员工私聊试点。正式机器人仍需绑定平台身份、接入麦米员工授权并完成双账号隔离验证。示例配置默认关闭。

## 管理员现在需要做的两件事

1. 已有全公司可搜索的钉钉机器人，继续沿用原应用。请确认它进 MagicAPI 的方式，是钉钉直接 HTTPS 回调并有原始 timestamp/sign 请求头，还是公司系统已接入 Stream 后再转送。只需回复模式和两个头是否存在。验签密钥仅在接收端作为只读文件挂载。先在 QA 入口验证明确以“麦米”开始的私聊，原物流与其他命令继续沿用原分支。
2. 确定由谁保管公司统一微信机器人的专用个人微信账号，并指定两名可分别登录麦米 IAM 的试点员工。待接收器和员工绑定上线后，由保管人本人在专用设备上扫码。扫码图、会话令牌和员工绑定码按登录凭据保管。

## 安装位置

| 功能 | 放在哪里 | 账号归属 |
| --- | --- | --- |
| 桌面个人 IM | 麦米 Windows 版的「IM 机器人」中添加钉钉或微信 | 钉钉机器人由使用者配置，微信由本人扫码。在本人专用的电脑和账号中使用，设置允许联系人的范围。 |
| 钉钉工作资料 | 桌面版内置 DWS 与麦米网关已实现的钉钉授权能力 | 每位员工单独授权查阅文档等工作资料。 |
| 公司统一机器人 | 需要在正式环境运行独立的接收服务，按发送人的绑定委派到该员工的工作区 | 企业应用凭据用于收件。员工操作权限由独立的麦米员工授权决定。 |

按钉钉作者与社区插件的说明，Stream 用于应用向平台发起长连接。微信的个人账号通道是 iLink 扫码和长轮询。两者都要能通过出站 HTTPS 访问平台实际使用的服务。扫码和消息链接会使用平台返回的地址，部署时应按 SDK 的受信地址与现场出站策略核对。

## 已核对的接线

- 现有 r105 正式网关基础镜像带有 enterprise_connectors、钉钉 CLI、MCP 和账号回调模块。现有企业连接器可核对公司身份和钉钉用户授权。资料查询、员工授权、向指定收件人发通知，与机器人入站接收是不同的流程。
- 另一个聊天「钉钉机器人」围绕 EIP 物流与 MES 发货单。现有机器人可复用同一接收入口，在原脚本内分流。钉钉平台验签密钥留在 EIP，EIP 转麦米使用另一把独立凭据。具体见《现有钉钉机器人接入》。
- 已审阅的 dsh-im 5.10.0 提供微信和钉钉通道，支持在宿主中列出工作区、改变会话和下达命令。公司入口必须在调用宿主之前验证员工绑定、权限和上下文。不要在任一员工工作区挂上统一机器人的凭据，或把共享会话当作所有员工的对话。
- company-im.example.json 是本项目的交接模板。Secret 字段是服务器内的路径。此模板尚不能直接传给 dsh-im 启动统一机器人。

## 开通顺序与验收

1. 当前交付针对原始 HTTPS 回调并在 EIP 验签。如实际链路是 Stream 后转发，先核对原 Stream 接收器到 MagicAPI 的认证方式。钉钉的 senderCorpId 与 chatbotCorpId 必须匹配配置的企业，robotCode 匹配接收机器人，senderStaffId 必须有明确的本企业员工映射。拒绝通过昵称、群管理员身份或聊天正文识别员工。
2. 个人微信缺少企业工号。员工应先登录麦米 IAM，领取短时一次性绑定码，在对应机器人的私聊中完成配对，并回到麦米核对绑定。绑定码仅存摘要、一次消费、短时有效，可撤销。二维码绑定的是机器人自身，不能替代每位发送人的员工身份验证。
3. 所有已验证的渠道消息都应先交给 routing.py，使用可信连接上的机器人标识和当前 IAM 员工状态。首版仅处理已绑定员工的私聊文字，拒绝群聊、附件和宿主管理命令。个人微信归属取自本次受信 iLink 安装及 sender 的绑定，不能由消息自行指定工号。
4. 工程端还要接入持久的重复消息登记、当前员工授权签发、固定工作区派发与同一私聊回复；双 AP 接收器需单活租约或明确的分片归属。领用 receipt_key 后才能派发。进程崩溃或结果未知时记录待核对，避免自动重放。解绑、停用、身份变更时撤销原委派与会话路由。
5. 使用两个合成员工测试同名会话、重复投递、跨企业消息、未绑定发送者、离职账号、撤销绑定、主机切换和结果不确定。之后由两名真实试点员工用无敏感内容核对各自回复，并确认无法访问另一人的历史。只记录分类型计数与延时。

路由策略在本机通过六项隔离和拒绝测试。identity_store.py 与 identity-schema.sql 实现了五分钟两端配对、到期清理、撤销、按绑定代次分隔会话和双接收器原子领用消息。只保存配对码和平台发送人标识的带密钥摘要。身份与路由密钥须由部署端安全生成并跨 AP 一致。PostgreSQL 16 临时库已运行四项数据库测试，包括两个独立连接并发领用同一事件，只有一个取得派发权。

另有默认关闭的钉钉 QA 委派分支，包括同源 IAM 浏览器配对、最长 15 分钟问答同意、本人模型代理调用和撤销。接入方式和双员工本机验证见《员工私聊委派QA》。实际平台接收、正式数据库部署、慢问答私聊取件的现场验证和真实员工验收仍待完成。接收器必须先提交领用事务再派发，派发和回送前还要重新核对当前员工授权和绑定代次。尚未启用公司统一机器人，也未启动账号或发送消息。
