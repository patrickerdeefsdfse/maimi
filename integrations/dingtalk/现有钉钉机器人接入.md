# 现有钉钉机器人接入

**先验证回调方式，再改 QA。** 现有机器人保留原应用、原消息入口和原有物流指令。只有私聊消息“麦米”、以“麦米 ”、“麦米：”等明确分隔形式开头才转给新接收器。直接发送单号、姓名日期及原服务命令继续原流程。“麦米饭”也继续原流程。

## 给维护 MagicAPI 的同事

1. 核对当前回调的入口和协议。如果钉钉直接 HTTPS 回调，且原始请求头含 `timestamp` 和 `sign`，可使用附件。若是 Stream 或其他系统二次转发，请告知转发系统已有的身份验证方式。此时不要去掉验签来让脚本通过，也不要把客户端可伪造的标志当成验签结果。
2. 在 MagicAPI 保存原脚本可回退的版本。在 QA 找到 `var wt = lgInputText.trim();`，**在这一行后**插入《MagicAPI-麦米私聊分流.ms》完整片段。原业务日志、原接口调用和所有原分支都留在原处。若当前版没有这个唯一锚点，先比较入口代码，把片段放在提取用户原始文字之后、业务日志及业务动作之前，不要整份覆盖。原有富文本提取可复用。
3. EIP 服务需能够读取下列设置。仅把路径与就绪状态提供给开发人员。不要在聊天、脚本源码或工单中填写真实密钥。

| EIP 环境变量 | 用途 |
| --- | --- |
| `MAIMI_IM_CALLBACK_MODE` | 通过原始钉钉 HTTPS 回调验证后才设为 `direct-https` |
| `MAIMI_IM_DING_SECRET_FILE` | 此机器人的 AppSecret 私有文件，仅供 EIP 验签 |
| `MAIMI_IM_FORWARD_KEY_FILE` | EIP 与接收服务共用的独立随机密钥，至少 32 字节，以文件原始字节为准，两边内容需完全一致 |
| `MAIMI_IM_RELAY_URL` | 内部接收服务的完整 HTTPS 地址，路径必须为 `/internal/maimi-im/v1/dingtalk`。待运维配置受信域名与证书后填写 |

脚本只传会话标识、平台消息标识、发送人的企业身份字段及文字，回复地址留在 EIP。正常分支直接使用验签通过的本次私聊回复地址，校验钉钉主机、路径和协议。网络异常时给出有限提示，不重投任务。该片段按项目测试时的 OpenJDK 17、MagicScript 1.9.0、MagicAPI 2.2.2 和 Spring 5.3 编译运行。

## 给麦米运维

接收器是内部独立 ASGI 服务 `magic_ingress:create_local_service`，由 Uvicorn 以 `--factory` 启动，加载 `routing.py` 和 `identity_store.py`，需要麦米网关已有的 IAM 目录模块和 psycopg。网关基础镜像中已有这两项依赖。把服务部署在内部受限网络并由受信 HTTPS 入口转发，只允许 EIP 源访问；不要对公网开放。脚本会拒绝明文 HTTP 和不匹配的路径。正常签名使用时间、随机数、方法、固定路径与原始 JSON 字节摘要，验证错误不派发。请求接受时间窗为 60 秒，机器时钟须同步。

服务端需要 `MAIMI_IM_CORP_ID`、`MAIMI_IM_ROBOT_CODE`、`MAIMI_IM_FORWARD_KEY_FILE`、`MAIMI_IM_BINDING_KEY_FILE`、`MAIMI_IM_ROUTING_KEY_FILE`、`MAIMI_IM_DATABASE_URL` 和及时更新的 `IAM_DIRECTORY_SNAPSHOT_FILE`。三把密钥各自唯一，由受限 Secret 提供。由数据库管理员在正确库单独执行 `identity-schema.sql`，应用仅需该 schema 的相应读写权限。两副本共用已验证的绑定与消息登记。当前代码未对生产服务做改动。

## 当前可验证的行为

| 试点私聊 | 应有结果 |
| --- | --- |
| 原单号、姓名日期 | 继续原流程 |
| 已正式建立绑定的员工发“麦米 状态” | 核对平台企业、机器人、员工映射和 IAM 目录，返回绑定状态。重复投递不重复返回结果 |
| 未开通用户发“麦米 状态” | 提示联系管理员 |
| 发送“麦米：请帮我……” | 默认关闭时返回维护提示；启用 QA 委派并经本人明确授权后可使用本人的模型进行单条文字问答 |
| 群聊、错误签名、过期回调 | 不进入员工服务 |

这里的“已绑定”需要受控的员工配对和有效的企业授权。持久化配对与去重已完成独立 PG16 测试。IAM 浏览器配对与本人模型委派已在默认关闭的 QA 分支通过双员工验证，接线见《员工私聊委派QA》。慢问答现有【任务编号 + 本人主动取件】的持久化 QA 实现。接线见《QA回调自检与慢问答》。正式站仍待现场验证。不要把网页 Cookie、共享机器人身份或平台 AppSecret 作为某位员工的麦米授权。

**本轮证据**：真实 MagicScript 合成验证见 `magic-validation.json`，真实 ASGI 与独立 PG16 鉴别验证见 `magic-ingress-validation.json`，绑定和并发去重见 `postgres-validation.json`。没有保存 MagicAPI 线上脚本、没有操作钉钉账号，没有发送员工消息。
