# 日常维护与容量

以下命令在部署目录的 `new-system/ops/changsha-desktop` 执行，不涉及旧项目清理。

`python3 maintain.py status` 只读检查本应用容器状态、Docker 数据盘余量和可用内存。输出不含密钥、Cookie、聊天内容或员工名单。磁盘低于 10 GiB 或 15%、可用内存低于 512 MiB、服务不健康/不足时返回状态 `attention`，退出码 2。它不是模型、真实 IAM 的可用性证明。

可以用公司现有监控每五分钟执行该命令，收集退出码与 JSON；这里没有擅自配置外部通知收件人。加 `--destination /公司挂载的备份盘/麦米备份` 可以同时检查最近备份是否超过 48 小时。真正的机外备份盘和告警接收渠道由公司运维提供，本地开发不能代替它们。

云端默认最多同时运行两个个人 Host，每个 Host 内存上限 1536 MiB、CPU 上限 1 核；未连接 Host 闲置五分钟释放计算资源，文件和历史卷保留。超出名额按先后顺序排队，界面显示位置，单次等待最多两分钟，不强停他人的活动会话。停止轮询 30 秒后自动离队；排队最多 128 人。该限制是同时云端使用人数，不是可注册员工数。本机聊天不占这两个名额。

按服务器内存和负载证据再调整 `PERSONAL_CLOUD_MAX_ACTIVE_HOSTS`。不能直接把它改成几百；当前架构没有证明一台 8 GiB 机器可以承载数百个同时活动的原生 Host。

## 停机备份

1. 选维护窗口，停止本应用 Compose 服务和本命名空间的个人 Host，保留容器和卷。工具不会自动停止聊天或其他系统。
2. 执行 `python3 maintain.py backup --destination /公司挂载的备份盘/麦米备份`。它只选择有本系统所有权标签的卷，以只读容器捕获 PostgreSQL、平台文件、个人原生日志和文件等卷；发现任意相关卷仍被运行中容器挂载就停止。备份期间不要并行启动或升级应用。
3. 执行 `python3 maintain.py verify --snapshot /上述返回的snapshot目录` 校验全部大小/SHA256。完成后再启动应用。
4. 服务配置、绑定挂载的秘密、TLS 证书以及更新发布私钥不包含在数据备份里，需要分别按公司秘密管理方式保管。备份含私有聊天/文件，目录权限为 0700、文件 0600，仍需使用公司加密备份介质。
5. 恢复时先在空的隔离 Compose 项目中恢复卷，保留归档中的数值 UID/GID，并使用相匹配的镜像/数据库版本和原加密配置。不可直接覆盖运行中的卷。不要把 SHA 校验通过等同于业务恢复成功。

本机已用合成卷验证真实 Docker 备份、内容读取和篡改拒绝。此脚本提供停机一致备份，不是在线热备、异地灾备或自动恢复系统。

## 数据清理与额度

个人云聊天沿用 90 天未活动后入回收区、再保留 30 天；项目文件独立保存，不随聊天删除。模型按员工个人 TokenKey 授权获取，插件仅可读取当前用户所在的运行环境。

文件请求大小、云 Host 内存/CPU/PID 已受限；卷的逐用户硬磁盘额度尚未启用。Docker 普通命名卷不能跨所有文件系统通用地设硬容量，需要长沙数据盘的 XFS/project quota 或独立受控存储支持，不能仅用定时清理宣称实现。部署初期应启用上述磁盘监测，并根据真实使用量配置公司备份和配额。
