# Windows 安装与自动更新发布

面向员工交付 NSIS 安装器，不再要求员工解压便携 ZIP。公司桌面保持 `com.megmeet.ai` 应用标识、`MEGMEET AI` 用户数据目录和 `MEGMEET-AI.exe`，安装器展示名称是“麦米办公助手”。聊天和工作区不放在安装目录里。DSH/企业扩展随完整桌面版本一起更新，保留适配器兼容性校验。

## 员工体验

正式 IAM（`https://iam.megmeet.com`）应用图标打开 `https://platform-ai.megmeet.com/maimi/`，提供网页聊天和桌面客户端下载。员工下载安装一次，之后桌面启动和每六小时检查更新，后台下载。用户正常退出后完成安装，下次自行打开新版。正在聊天时不强制退出；系统关机/注销时不执行更新。帮助菜单显示更新状态并可手动检查。

首次安装采用向导，先选择本人可写的安装目录，再安装。固定为“当前用户”，不提供所有用户模式，不申请 UAC 提权。正常更新明确使用软件当前所在目录；中文和空格路径已经纳入真实 NSIS 演练。工作区和聊天资料仍在用户数据目录，改变安装目录不会搬动或删除它们。

安装前扫描本次完整有效载荷，按固定解压器的 Windows 路径限制计算允许的目录长度，不使用旧版本常量。0.8.0 的 47,628 个文件中，最长相对路径为 180 个字符，因此安装目录当前最多 78 个字符（包含向导自动添加的应用子目录）。目录页会说明上限，过长时“下一步”不可用；请选择较短的本人可写目录。静默更新 `/D=` 也在卸载旧版或写入文件之前检查，超限退出码为 4，保留原软件。不是允许任何长度的路径；今后版本的上限可能随实际依赖变化。已有超长目录应手动选择合规短目录，不能靠自动更新绕过限制。

每次启动会清理本更新器遗留的安装包和中断临时文件，只保留仍有效的待安装候选/未完成尝试，不递归清理，不删除任意 EXE、聊天文件或链接。交接安装时记录尝试；五分钟内重新打开旧版会显示“正在安装”并暂不重复交接。安装较慢时，继续核对本次安装进程的 PID、程序完整路径和创建时间，最长等待一小时；不会枚举其他进程或读取命令行。若安装已结束但仍运行旧版，提示上次更新未完成，下一次正常退出再尝试。只有实际启动新版才确认安装成功；进程存活不能证明已升级完成。

新安装器判断当前安装目录内的完整程序路径，不阻塞其他目录的同名开发/便携实例；它不会终止仍在运行的目标程序。边界：已经发布的 0.5.0 卸载器采用旧的同名进程检查，第一次升级时它仍可能要求先关闭另一个同名开发版；从新安装器生成的版本继续升级才完整使用路径检查。不会修改既有发行或强杀进程来绕过它。

页面不是 OAuth 回调，注册的 `https://platform-ai.megmeet.com/v1/iam/callback` 保持原样。IAM 应用图标是否已建立、应用首页地址是否已配置，必须以同事的后台配置为准，截图和接口文档不能证明已配置。下载页面没有员工信息、个人 Key 或服务器密钥；软件内的 IAM 登录继续校验授权。

## 更新信任与实际边界

桌面只访问固定公司 HTTPS 更新地址，拒绝跳转，验证内置 Ed25519 公钥签名、有效期、平台、版本、递增发布序号、长度及 SHA256；退出安装前再次验完整性。凭据和浏览器 Cookie 不发送给下载站。网络失败保留当前软件，已验证且未过期的完整候选可在退出时安装。

发布私钥仅在维护电脑 `%LOCALAPPDATA%\MEGMEET\release-signing\desktop-ed25519.pem`，只授权当前用户和 SYSTEM。它不在源码库、服务器 ZIP、下载站或客户端内。应按公司方式另行离线加密备份；丢失它会阻止现有客户端信任后续更新，不能随意重新生成。客户端只包含公钥。当前没有 Windows Authenticode 企业代码签名证书，首次下载可能出现 Windows 未识别发布者提示；此状态与更新清单签名不是一回事，不宣称已有企业发布者签名。

更新下载完整安装包，当前没有增量差分节省流量。清单有效期一年，应在到期前重新签发。长期离线电脑联网后才会更新。当前目标为 Windows x64；不是 Mac/Linux 桌面安装包。

## 后续发布步骤（维护方）

1. 本机修改、测试后提升 `desktop-local/package.json` 和锁文件版本。现有发行版本不可覆盖。
2. 使用固定工具版本与缓存构建公司桌面；0.8.0 通过 `MEGMEET_PACKAGE_RUNTIME` 指向已验证的独立 alpha.2 候选，保留普通 alpha.1 runtime。依次运行 `refresh-owned-asar.cjs --company`、`audit-packaged-candidate.cjs --company`；前者恢复打包工具规范化的package.json为冻结源码，后者确认250个同版DSH包、办公引擎和独立工具组件的全部清单与字节。后续改动也必须重新审计。
3. 本目录通过 `npm ci --ignore-scripts` 安装固定 `electron-builder 26.15.3`；`node build.cjs` 生成 `new-system/releases/installer-版本/MEGMEET-AI-Setup-版本-x64.exe`。这一步不上传。
4. 用原签名密钥执行 `node release-signing.cjs publish 安装器绝对路径 下载站site绝对路径`，校验清单与安装器。只有第一次准备维护环境才使用 `init`，它不会覆盖不同的现有公钥。
5. 用 `ops/desktop-distribution/package.py` 生成新的公开下载站 ZIP，上传长沙并按其 README 切换该独立服务挂载。保留当前与上一版安装器，保证已开始下载的旧链接仍存在。

普通运行时和服务器都不需要安装 npm 或接触发布私钥。每次升级都本地构建验证后发布，员工端自动检查；不会自行追踪未经验证的 DSH 上游版本。

## 验证依据

`desktop-local/tests/updater.test.cjs` 检查签名、平台、过期、降级、篡改、重定向、断流、重复检查、退出和 Windows 安装标记；`window-lifecycle.test.cjs` 用实际主进程模块验证重复退出也等待 Host 停止。`rehearse.cjs` 使用独立临时应用标识实际运行 Windows 安装/升级/卸载，以及真实更新器交接 NSIS，保留合成员工文件，不操作真实员工数据。

使用的安装器选项依据 [electron-builder NSIS 官方文档](https://www.electron.build/v26/docs/nsis/)；采用固定版本的标准脚本和自定义“等待退出、不杀进程”扩展。

`benchmark.cjs`（`rehearse.cjs` 同入口）以独立 NSIS 应用标识比较 7z 与 ZIP 提取，逐个核验 1208 个合成文件，同时验证同名外部进程、运行中目标拒绝、签名更新后原目录及数据保留。`benchmark-full.cjs` 读取已审计公司版的完整目录，用另外的临时应用标识安装但绝不启动员工应用，对全部文件逐个 SHA256 验证并卸载；过程每 30 秒写进度。不裁剪未经验证的 DSH 文件。

2026-09-18 本机完整载荷测量使用已冻结公司版 0.5.0 的全部 23,161 个文件、717,159,994 字节，采用独立合成安装身份：

| 方案 | 本机测量与结论 |
| --- | --- |
| 原 7z 分阶段提取与复制 | 连续复制 989 秒后完成 9,533 个文件；为停止长时间实验，仅终止本次自有测试安装器。未完成，因此不能给出完整安装耗时或加速倍数。 |
| ZIP 直接提取，过深临时目录 | 首个 261 字符路径失败，退出码 2；这是未加入前置保护的试验，不能发布。 |
| 同一完整 ZIP，合规中文与空格目录 | 安装 67.372 秒，退出码 0；全部 23,161 个文件 SHA256 与原成品一致，卸载 8.173 秒，合成聊天数据保留。 |

因此固定使用 `differentialPackage:false`、`useZip:true`，结合前置路径限制。此测量是本机同一完整旧版载荷的技术对比，不是对所有员工电脑或最终 0.6.0 安装时间的承诺；磁盘、防病毒和并行任务都会影响耗时。0.6.0 的动态目录上限另用其最终真实最长路径做边界演练：79 字符目录的新装和静默更新均在写入前拒绝；78 字符中文与空格目录的最深文件安装、原地升级、卸载保留数据均通过。

证据：`desktop-local/evidence/installer-full-payload-zip-short-path.json`、`installer-full-payload-benchmark.json`、`installer-full-payload-zip-benchmark.json`、`installer-path-policy-rehearsal.json`、`installer-optimization-rehearsal.json`。两个归档格式的验证器实测见 `installer-archive-formats.json`。保留失败记录，不将中间试验当发行通过。

## 随版本冻结的社区插件

0.6.0 随完整运行时纳入固定上游提交的四个 MIT 插件：文件变更查看、外观设置、小组件和使用统计；不在员工启动时联网安装最新版。文件变更插件关闭写入补丁工具，外观保留原主题，小组件关闭参考小组件，使用统计的第三方供应商列表为空。统计插件不代表 TokenKey 的实际账单，也不向它配置员工 IAM 或个人 Key。

上游原始 `/ext` 接口本身没有统一认证，已通过独立且校验 SHA 的包装器接入 DSH 原生 Cookie/Origin 检查，失败则拒绝；不修改第三方原文件。真实无外部网络 Host 和 Windows `startHost` 外层均验证四个插件：有合法 Cookie 可读、匿名拒绝、跨 Origin 拒绝，客户端模块可正常加载。实际原生浏览器打开四个设置面板无页面错误；完整四包文件哈希和包装器随运行时封装校验。证据见 `desktop-local/evidence/community-plugins-host-probe.json`、`community-plugins-desktop-probe.json`，详细来源与限制见 `dev-local/dsh/community-plugins.README.md`。

这不隔离同一 Windows 账号下的其他程序：该账号仍能读取本人文件和运行时凭据。也不等同企业项目插件的服务端授权；项目插件继续由已有目录/ACL校验。0.8.0 增加独立钉钉、搜索、浏览器操作与电脑操作工具；钉钉与搜索需要公司配置相应服务，电脑及浏览器操作由员工主动选择并受本机确认与停止控制。原生插件管理仍使用 DSH 界面。
