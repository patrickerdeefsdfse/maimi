# 原生个人入口：双账号候选

本模块把身份与路由放在 DSH 外部。复用当前已验收的原生 DSH 镜像，不修改品牌、人物、标题、聊天布局或首次提示配置。

## R4：修正空子协议头，补齐 WebSocket 诊断

R3 运行到初次 WebSocket 检查时报 `InvalidStatusCode`。按固定顺序至少 A 的工作区 HTTP、页面、静态资源 URL 和伪造身份 HTTP 已完成；缺少每用户进度标记，不能确定失败是 A 还是 B。实际握手拒绝码未记录，不能声称 DSH 已证实返回 400。

本地真实 TCP 重现一个协议缺陷：`websockets` 在 `subprotocols=[]` 时发送空 `Sec-WebSocket-Protocol`，严格服务端返回 400；传入 `None` 则省略该头并成功握手/消息往返。R4 将无子协议的情况改为 `None`；有子协议时保留原列表。公共 Origin、可信 SSO、本人 Host/Cookie、内部地址及网络目标规则不变。

离线检查新增逐账号/逐阶段进度以及安全的 WS 状态诊断，区分入口拒绝、上游拒绝和直接上游对照；对照成功不覆盖原始失败。不输出 Cookie、令牌、任意异常正文或地址。本包仍只运行临时资源，尚未生产部署。

## R3：分开浏览器地址与 DSH 内部地址

R2 已在服务器确认：模拟 SSO 返回 200；DSH 使用公共 Host/Origin 时返回 401，增加 HTTPS 转发头仍是 401，同一私有 Cookie 使用本机 Host/Origin 时返回 200。两个个人 Host 初始化、资源清理和现网三服务未变检查通过。尚未细分究竟由 Host、Origin 或其组合触发拒绝，不宣称已验证真实 SSO 或浏览器。

R3 保留入口原有的公司 SSO、浏览器公共 Origin、本人绑定与 Cookie 校验。通过验证后，HTTP 的内层 Host/Origin 固定为 `127.0.0.1:3085` / `http://127.0.0.1:3085`；WebSocket 使用同一内层握手地址，实际连接的网络目标仍由本人 `binding.upstream` 指定，绝不连接入口容器自身回环地址。客户端不能选择该目标。

检查继续使用临时实例，并增加内部地址下页面/API 的无 Cookie 和跨 Host Cookie 双向拒绝测试，以及 HTML/结构化启动数据中资源 URL 的公共同源检查；保留正确用户 HTTP、原生 WS 握手、伪造身份拒绝、A 重建恢复与 B 不变检查。R2 诊断仍保留。URL 静态检查不代表浏览器执行或资源获取已通过；候选通过后还须验证浏览器启动资源、实际 SSO、两轮模型回复和历史。不在本包部署真实入口或修改原生 UI。

## R2 历史：补充首个 HTTP 失败诊断

R1 已在服务器确认两个临时 Host 均初始化成功，Linux 启动保护通过，但首次经入口调用工作区接口收到非 200，R1 漏记实际状态码。该轮退出 1，清理及现有 Host/Gateway/Nginx 未变检查通过；原因尚未确认。

R2 保持 `entry_app.py`、`host_launcher.py` 与 R1 完全一致，只增强离线检查：输出请求所处阶段、准确 HTTP 状态或限定错误类别；用同一个临时 Host 的私有 Cookie，对公共 Host/Origin、固定 HTTPS 转发头及本机 Host/Origin 做直接对比。不打印响应正文、请求头、Cookie 或令牌。即使对比请求成功，原始失败仍保留，不将其记为联调通过。

这不是生产修复包，也不更改任何现网配置。R1 临时实例已清理，R2 会新建本轮独立临时实例并在结束后清理。真实 SSO 和模型仍不访问。

## 已编写的候选代码

- `entry_app.py`：HTTP 与 WebSocket 都校验公司 SSO；可信工号映射固定内部用户 UUID，再选择本人 Host。浏览器传来的 Host 凭据、用户头、Referer 不参与选人。SSO 错误时拒绝访问，不回退共享 Host。
- `host_launcher.py`：只挂本人状态卷，启动原生 DSH 后通过已验证的 `workspace/create` 登记 `/state/work`，就绪前不开放转发。重启核对原工作区 ID。DSH 的私有访问 Cookie 只给入口服务读取。
- 模型请求通过入口内的固定 TokenKey 转发。个人 Host 仅持有本次分配的内部模型凭据，不能读取公司 TokenKey。双账号候选只启用 `deepseek-flash-v4.1`。
- 两个 Host 的卷与内部网络分别独立；不向 Agent 或公开入口挂载 Docker socket。

入口配置中的 `user_id` 必须来自现有 `platform.users.id`，`user_no` 使用公司已确认长期唯一的工号。当前代码只接纳两个明确绑定的身份。组织变化不改变个人归属。

## 这次服务器命令做什么

`bash start.sh` 后台执行候选检查：使用两个合成身份、两个临时个人 Host 和一个临时入口；SSO 是仅注入到离线测试实例中的模拟响应，Host 与入口使用实际代码、真实 DSH HTTP/WebSocket。

不访问真实 SSO、TokenKey 或用户数据，不读取现网密钥，不修改 Nginx、Compose、数据库或现有容器。测试创建的临时容器、网络和卷带本次专属标记，结束只清理本次资源；保留检查日志。镜像使用现场已确认的不可变 ID，不联网拉镜像、不安装依赖。

此检查需要约 3.5 GiB 可用内存；不足会停止，不清 Swap 或停止其他服务。检查期间临时增加有限资源负载。

## 必须保留的验收边界

本地单元测试和服务器离线候选通过，都不等于真实公司账号已接通。真实 SSO、浏览器首次自动选择、两轮模型回复、历史恢复和两个真实账号的相互隔离仍须后续实际验证。

当前没有部署生产身份入口，也没有实现大规模 Host 调度、闲置回收、排队或项目插件权限。两个 Host 固定启动仅用于小规模接入验证；不能据此承诺数百上千同时在线。

当前候选 HTTP 请求与 WS 单条消息上限 8 MiB；大文件上传需独立验收。已有共享 Host/REST 历史不会自动迁移进个人卷。项目继续放在最后。

## 真正启用入口前

1. 候选实际 DSH 协议检查通过。
2. 在服务器本地输入两个测试工号，复用数据库 UUID；不回传工号、Cookie 或凭据。
3. 配置两个个人持久卷、私有网络与最小模型代理；真实 SSO TLS 校验保持开启。
4. 根据现网相关 Nginx 完整区块接入页面、根 API、插件资源及 WebSocket；不能再以 Referer 判断用户。
5. 分别用两个真实浏览器账号验收首次直接聊天、两轮回复、历史、相互不可见、刷新与重建恢复。

本包没有生产切换命令。运行候选检查不会改变当前 DSH 入口。
