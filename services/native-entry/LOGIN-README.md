# 原生个人入口：公司登录与打开页面时恢复登录

范围：ENTRY_LOGIN_ONLY。保留已验收的原生DSH界面、个人Host镜像、工作区和历史。

已确认的门户源码使用 /v1/oauth/login，redirect_uri 为编码后的本站地址，
client_type 精确为 [web]。本候选将返回目标固定为本站 /megmeet-ai-native/；
真实公司SSO是否允许这个子路径仍需部署后的浏览器验证。

未登录打开原生首页时，页面尝试一次同源POST refresh-token（无请求体），
浏览器自行接收Cookie，再查询个人身份入口。验证成功才进入原生页面。
需要重新登录时可点“公司登录”；网络或服务暂时故障保留重试和登录链接，
不会自动无限跳转。不会读取、显示或写入浏览器Token，不重放聊天请求。

这不是聊天过程中的定时续期，也没有新增退出功能。这两项仍是后续工作，
不能因本次检查通过就标记完整登录生命周期完成。

部署仅适用于已经成功运行的megmeet-personal-pilot R1。先验证当前源码、
镜像、配置和服务归属，再备份入口文件，更新入口并重建entry服务。
两个个人Host和Gateway保持运行；Nginx只测试与重载，以更新入口容器地址，
不修改Nginx配置。若部署验证失败，安装器尝试恢复此前入口代码和服务。
入口重建期间连接会短暂中断，请等当前聊天回复完成后执行。

运行方式：将ZIP上传至/data，核对SHA256后解压到独立目录，执行start-login.sh。
脚本后台运行；读取其打印的日志路径获取最终LOGIN_ENTRY_UPGRADE_EXIT。
探测只使用不带Cookie的固定本机HTTPS入口，不访问真实账号或调用模型。

通过部署检查后，只新增以下浏览器验收：

1. 新的无痕窗口打开 https://platform-ai.megmeet.com/megmeet-ai-native/。
2. 点击公司登录，完成登录后应回到原生DSH并自动打开自己的工作区。
3. 正常登录的浏览器刷新同一入口，应直接进入原生界面。

只需回报成功或出现的错误文字，不回传Cookie、Token、工号或业务聊天。

不要用本包覆盖或重建之前的pilot R1归档，不运行旧pilot安装器来应用新代码。
