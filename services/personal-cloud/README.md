# 每员工原生云端工作区

此服务是 Linux DSH 0.1.6-alpha.1 的真实原生 Host，个人聊天、原生会话记录和文件在服务器的两个独立 Docker 卷保存。它不是部门共享聊天，也不使用多人共用的模型密钥。个人目录由经过 IAM 验证的稳定工号映射；请求不能指定员工或任意容器、镜像、挂载、启动命令。

桌面默认仍使用个人本机原生 Host。固定“云端工作区”入口只读取元数据；用户点击才调用 `/v1/personal-cloud/open`，桌面切到同一受控浏览器来源下的服务器原生页面。不能改名、删除，原生 create 只能返回 `/workspace`。这些限制植入 Host 工作区命令层，HTTP 和 WebSocket 两种入口均受约束。旧部门/小组数据保留，公共入口由平台退休。

Gateway 不挂 Docker socket。私有 manager 只创建已固定镜像策略的 worker；worker 为 UID1000、只读系统根、无 capabilities、禁止提权、内网、1536MiB RAM、1 CPU、128进程，没有端口发布、宿主目录或 Docker socket。manager 本身需要 Docker socket，属于服务器管理员权限边界，不能暴露给桌面或公网。

默认最多2个运行 Host，超出进入有界先到先服务队列，原生界面显示排位并每5秒重试，单次等待最多2分钟。队列最多128人，停止轮询30秒后失效；该限制不限制员工账号总数。已断开连接且300秒空闲时停机，持久卷保留。有效 WebSocket 保持 Host 活跃。应用授权在原IAM期限内续期后，通过私有心跳延长当前Host租期；登录实际到期、退出或撤权时停止访问，已连接WebSocket最多5秒断开。模型只持有工号/登录会话绑定lease，每次调用重新校验；IAM凭据和个人真实TokenKey不会注入worker。

## 部署文件

`dev-local/compose.yaml` 包含合成本地经理凭据和网路，不能作为公司凭据使用。`ops/changsha-desktop/personal-cloud.compose.yaml` 是公司候选叠加配置；配置向导生成独立调度凭据，start-server.sh 自动合并，离线清单校验 Gateway、manager、worker、PostgreSQL、Redis 五个镜像。未访问或部署长沙。

## 当前边界

- 2个活跃Host加有界排队仍不是千人同时在线容量；须根据真实内存、模型额度和压测结果扩容，不能仅提高配置值。
- 普通Docker卷提供持久隔离但没有逐员工硬磁盘额度；线上须为卷数据盘配置可执行的项目配额、磁盘告警和备份。现有文档/插件上传额度不等于原生工具文件系统额度。
- 原生Host可操作自身卷并通过个人模型lease调用授权模型，但worker内网禁止任意互联网访问；插件或联网工具后续需要审核后的专用出口。
- 同一员工多个设备目前共用一个云工作区，新应用登录接入会轮换Host会话并断开旧连接；数据保留，尚不是并行多设备编辑冲突协作系统。
- 当前权限撤回后尚有最长5秒的原生WebSocket关闭窗口；已发送给客户端的文本不能撤回。
- native adapter固定DSH版本并校验编译命令锚点；升级必须重建/回归，不宣称任意新版本自动兼容。

社区扩展固定源码与构建文件摘要，和DSH作为同一候选验证。它们的 `/ext/` 路由必须经过Gateway员工认证和worker的routeToken保护；原生DSH端口只绑定容器loopback且不发布。不要把原生端口直接暴露到共享网络。状态检查、离线停机备份与机外备份边界见 `ops/changsha-desktop/MAINTENANCE.md`。
